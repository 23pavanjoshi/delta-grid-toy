## About the Assignment

I've worked on card-based games before, so I was already familiar with the core gameplay concepts like card flipping, match evaluation, state management, and handling continuous player input.

That allowed me to spend more time on the details that make the game reliable, such as handling different grid layouts, making the shuffle deterministic, ensuring save/load restores the game correctly, and covering edge cases that can happen during gameplay.

## What I Learned

The biggest learning for me during this assignment was setting up Unity EditMode tests with custom Assembly Definitions.

I ran into a few issues with assembly references and test discovery before getting everything working correctly. It was a good opportunity to understand how Unity's Test Framework works internally, and it's something I'll definitely use in future projects.

## What I Think This Assignment Was Testing

To me, this assignment wasn't really about building a memory card game.

It was about demonstrating how a developer approaches a problem, structures a project, documents decisions, and handles the small details that make software maintainable.

Features are important, but so are architecture, code quality, testing, documentation, and the reasoning behind technical decisions.
